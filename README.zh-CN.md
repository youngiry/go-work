# Go Work：让智能体用成果证明完成

**“我会继续工作。”然后就停了。Go Work 在收尾时检查实际成果。**

[English](README.md) · [接入说明](docs/integrations.md) · [任务约定与协议](docs/protocol.md) · [反馈问题](https://github.com/youngiry/go-work/issues)

Go Work 是运行在本地的 AI 智能体完成检查器。它根据任务约定核对交付物和验证结果，发现缺项就通过 Hook 或宿主接口要求继续执行具体工作。运行过程使用 Python 标准库。

## 重点处理的情况

| 情况 | 判定依据 |
|---|---|
| 声称“已经全部完成”，交付仍有缺项 | 实际文件、修改基线、验证程序结果 |
| 复述用户观点、赞同“你说得对”，随后收尾 | 验收缺项与成果进展 |
| 说“我会继续”，随后结束 | 承诺文本与实际进展的差异 |
| 承认提前结束、道歉、保证继续，随后又停 | 专门的回归测试覆盖这一循环 |
| 反复输出相似保证 | 回复相似度与连续相同成果指纹 |
| 完成一个文件或中间步骤后收尾 | 整体任务中的剩余验收项目 |

**文本信号用于解释，实际证据决定是否继续。** “太好了”配合合格交付可以正常结束；单纯的工具调用次数也只作为辅助观察。中英文措辞识别采用轻量规则，引用和否定表达可能产生提示误差，验收结果始终具有决定权。

## 安装与接入

```sh
git clone https://github.com/youngiry/go-work.git
cd go-work
python -m pip install .
go-work config --adapter codex
```

配置命令只输出待合并的内容。Codex 对应 `.codex/hooks.json`，Qwen Code 对应 `.qwen/settings.json`；DeepSeek Harness 使用其上游实验性桥。按照各宿主提供的信任入口审阅配置，再由助手为当前任务建立约定。详见[接入说明](docs/integrations.md)。

```sh
go-work arm --session <真实会话ID> --contract contract.json
go-work status --session <真实会话ID>
go-work pause --session <真实会话ID> --reason "等待作者选择论证方向"
```

任务约定示例在 `examples/contract.json`。助手负责整理交付要求与启用时机，用户继续使用自然语言布置任务。当前版本采用显式启用；纯讨论保持原有交互。新用户消息会暂停旧约定，助手按最新要求重新启用。

## 兼容范围

- **Codex：** 原生 Stop Hook 适配，协议与进程测试已覆盖，桌面真实启用待验证。
- **Qwen Code：** 官方 Stop Hook 协议适配，协议测试已覆盖，真实启用待验证。
- **DeepSeek Harness：** 支持实验性 Codex Hook 桥的协议；该桥传来的最后回复为空，因此此模式主要执行成果检查。旧版安装可能需要升级或自行编写原生接入。
- **其他智能体：** 通用 JSON 协议适用于提供停止前检查和续跑接口的宿主。DeepSeek、Qwen、Kimi、GLM、MiniMax 等模型可在这样的宿主中使用；适配能力由宿主接口决定。

## 控制与边界

默认最多续跑 6 次，连续 3 次成果保持相同状态后交还控制权；90 分钟阈值在收尾检查时生效。状态按会话隔离。用户中断、权限和异常处理沿用宿主机制。通过 `pause` 可明确暂停任务。

检查分为文件检查和用户配置的可信验证程序。文件检查覆盖存在、大小、约定文本与本轮变化；验证程序按退出码判断。代码测试、计算结果校验等适合使用验证程序；论文论证、事实解释和审美质量继续通过实质审阅判断。

Go Work 属于工作流可靠性工具，与智能体共享本地权限。运行状态保存在本地，包含目标、路径、检查配置及用于重复检测的文本片段哈希（输入上限 12000 字符）；应按任务敏感程度管理。事件摘要保存信号与状态，程序采用本地处理。

项目按 **MIT** 许可开放。欢迎提交真实复现、更多宿主适配和测试；公开反馈时请先替换私人任务与资料。
